# Kicks Ride — project handover

Personal indoor training app for Jim (Manchester, UK; metric units; motion designer, 20+ yrs After Effects / Cinema 4D / Blender).
Started 8 Nov 2026 in a Claude chat; this file is the handover so Claude Code sessions start with full context.

## What exists today (web prototype, working)

Live: https://mrjimcampbell.github.io/kicks-ride/ · Route Explorer: https://mrjimcampbell.github.io/kicks-ride/concepts/
Repo: github.com/mrjimcampbell/kicks-ride (public, GitHub Pages from `main` root). Local copies also in `~/claude/kickr-ride/` (not a git repo).

- `index.html` — single-file app: three.js 0.160 (CDN import map) + Web Bluetooth. Runs in Chrome (Mac) and the Bluefy browser (iPad/iPhone; normal iOS browsers have no Web Bluetooth).
  - **FTMS (0x1826)** connection, auto-detects bike (Indoor Bike Data 0x2AD2) vs treadmill (Treadmill Data 0x2ACD). Control point 0x2AD9 writes serialised, waiting for indication responses.
  - Bike: Course (sim gradient 0x11 with difficulty %), ERG (0x05), fixed grade; physics speed from power/slope/mass (rider kg + 8 kg bike, default rider 69 kg); KICKR's own speed shown for calibration.
  - Treadmill: pace-first HUD; incline modes Course / Fixed / **Off (flat, never touches incline)**; Set Speed (0x02), Set Incline (0x03); never sends START to a treadmill.
  - Heart-rate strap / footpod (0x180D, RSC 0x1814) separate connect.
  - Workouts: library + quick builder. Run: distance reps @ pace, time recoveries @ km/h, incline per block, warm-up/cool-down, or steady pace-capped. Ride: FTP-% ERG blocks. Player: auto speed/incline/ERG per block, 3-2-1 beeps, pause/skip/end, auto-pause when belt stops, resend speed if ignored.
  - Recording → TCX with a lap per workout block; Finish & save; **direct Strava upload** via relay; CSV calibration log; snapshots (manual + max 3 random auto) with stats overlay.
  - HUD text size Normal/Large/XL (Jim runs without glasses — big numbers matter). Bluetooth explorer + copyable log.
- `concepts/index.html` — Route Explorer: keyboard/mouse fly-through of environment moods (highlands default, dawn, coast, night) with Blender models.
- `models/` — `rider.glb`, `runner.glb`, `scots-pines.glb` (script-built placeholders; Jim considers characters far short of the bar). Source: `~/claude/kickr-ride/models/kicks-ride-models.blend`.
- `strava-relay/worker.js` — Cloudflare Worker `https://kicks-ride-strava.jim-campbell.workers.dev` (/token, /refresh, /upload, /upload/:id). Holds `STRAVA_CLIENT_ID=295158` (var) and `STRAVA_CLIENT_SECRET` (encrypted secret, reset 8 Nov). Strava callback domain: mrjimcampbell.github.io. Never put the secret in code or chat.

## Hardware facts learned
- **Reebok FR30z treadmill**: FTMS works; accepts speed AND incline control. Belt reports 0.5 km/h when starting → treat >0.3 km/h as "moving". Sometimes ignores speed commands while ramping → resend after 5 s.
- **Wahoo KICKR Bike Shift**: FTMS works (power, cadence, sim, ERG). Gears/hood buttons are proprietary Wahoo BLE (unexplored).
- Bluefy needs **full 128-bit UUIDs** (no `'fitness_machine'` aliases) and may report characteristic UUIDs in short form — normalise when matching.
- Gym: Concept2 BikeErg (PM5, publishes its own BLE spec) — possible later display/record-only mode.
- Apple TVs: living-room 3rd-gen 4K (A15) → moving to the gym as the main treadmill unit; buying the newest model. Samsung Frame TV in front of the treadmill. Also iPhone, iPad mini (back-burner), Mac Studio (Blender, C4D trial ending, Xcode installed), MacBook Pro.

## Decisions (11 Nov 2026) — the new direction
1. **Park the bike/world-building. First goal: something Jim actually uses daily** — treadmill intervals on a **400 m athletics track**.
2. **Native Apple apps** (Swift). tvOS has no WebView, so the TV renders with **RealityKit** (USDZ assets). The three.js web app stays as a quick look-dev sandbox.
3. **iPhone = the brain**: owns the treadmill BLE connection, workouts, recording, Strava. Must work fully headless (Jim may just watch YouTube). Rich workout builder + library (Jim also asks Claude to author workouts in plain language).
4. **Apple TV = display + big HUD** joining over the local network (Network.framework / Bonjour). Phone shows a stripped HUD + controls (stop, snapshot, skip) — like Zwift Companion. Keep a shared Swift package so roles could later be swapped (TV as standalone driver).
5. **Arena**: bought "Track And Field Arena" by JG3D (Fab). Jim has the .blend, USDZ, textures and a PDF. ~254k verts, 3–4K textures → slim for tvOS (decimate where safe, 1–2K textures, KTX/ASTC). **Paid asset: never commit it to the public repo** — keep under `assets/` and gitignore it.
6. **Exact 400 m**: lane 1 measured 0.30 m from the inner kerb; straights 84.39 m, inner kerb bend radius 36.5 m. Verify/rescale the arena's track; overlay an exact-spec track surface if its markings are off. Runner position = treadmill distance mod 400 along lane 1 (or a chosen lane, scaled).
7. Free Apple developer account for now (7-day reinstall: run `tools/install-iphone.sh` in your own terminal with the phone plugged in; signing needs the login keychain, which the sandboxed shell can't read). Paid account if it gets annoying.

Jim mostly uses standard and low rear.
- **Arena pipeline**: `tools/arena/build_arena.py` (run headless, see its docstring) → `assets/arena/build/` (gitignored): `arena.usdz` + `arena-appletvos.reality` / `arena-appletvsimulator.reality` (realitytool, GPU-compressed). A tvOS build phase copies the matching one in; without it the app draws an exact-spec placeholder.
  - Strips whole elements, never decimates (Jim's call): Net + Pillars (discus cage) gone → 196.5k → 144k verts. Cameras/lights stripped.
  - Textures sized by visibility (Track2.0 atlas BaseColor 4K, Stand/ChainLink/other Track2.0 2K, tiling grass/asphalt/rubber 1K); near-flat roughness maps → constants. Jim may replace textures wholesale later; normal/roughness use to be revisited during look-dev.
  - Gotchas handled: Blender's USDZ packer drops images shared by two materials (so: .usdc + Apple `usdzip`); Track2.0 BaseColor/Roughness get written as .png while referenced as .jpg (converted with sips). ChainLink_BaseColor must stay PNG (alpha).
- **Arena track measured (not to spec)**: real metres, unit scale 1; track centre Blender (−6.420, 4.002), surface z 0.538. Inner kerb radius 35.596 m, straights 82.612 m, 8 lanes × 1.369 m → lane 1 ≈ 390.8 m. Decision: don't rescale; `TrackGeometry.jg3dArena` + `nominalLap = 400` maps 400 m of treadmill onto one lap of the arena's own lane 1.
- **Runner pipeline**: Mixamo FBX clips (In Place, with skin) in `assets/runner/` → `tools/runner/build_runner.py` (headless Blender) → `assets/runner/build/runner_<clip>.usdz` (gitignored), copied in by the tvOS build phase. It prints each clip's natural speed (planted-foot ground speed at rate 1), which goes into `RunnerAnimator.clips`. The app uses the run file as the character and plays every clip on that rig, picking the clip by belt speed (hysteresis + 0.35 s crossfade) and setting playback rate = speed / natural speed (clamped). Clips are chosen by **step length** (cadence = speed ÷ step when foot slide is zero), matched to Jim's Garmin data: ~1.02 m step / 160–168 spm at 10 km/h (treadmill, wrist cadence) → ~1.32 m / 172–175 spm at 14 km/h; treadmill and road cadence follow the same trend. Bands (natural speed, step): walk <7 km/h (4.9, 1.07 m); jog "Jogging" 7–11.3 (8.2, 0.97 m, 3 strides per loop); run "Running_02" 11.3–15 (10.9, 1.26 m); fast "Medium Run" 15–19.6 (14.5, 1.55 m); sprint "Running" 19.6+ (20.1, 1.96 m; also the character mesh). Unused downloads: Running_slower, Standard Run, Run Forward. Idle while stopped: "Arm Stretching" (17.7 s) / "Neck Stretching" (6.4 s), alternating with 0.8 s crossfades. Mixamo's speed slider only changes playback rate, not gait. Character is currently the free skeleton (1.80 m), bone-ivory material.
- Pushing: Claude's sandboxed shell can't read the keychain; push via the user's Terminal panel (`gh` is logged in).

## From the original chat (8–11 Nov) — details and ideas not captured above
**Workouts (how Jim trains).** Typical session: 8 × 400 m with ~1 min walk recoveries; also 800s, 1 km reps, pace-capped easy runs. Rules: reps end on *distance*, recoveries on *time*; targets are *pace* (converted to belt speed); per-block incline; warm-up/cool-down. Quick-builder form first (≈4 taps for 8 × 400), full block editor later. Jim doesn't use ZWO files (they never controlled the treadmill); used Kinni for intervals (flaky). Often he'll just ask Claude to write a workout in plain language. Bike: ERG blocks as % FTP; Jim rarely does bike sessions but might with full control.
**Treadmill control details (keep in the port).** App never starts the belt; treadmill's own stop/buttons always win. Incline: ≥4 s between changes, ignore changes < 0.5 %. Speed: send as soon as belt > 0.3 km/h; if not at target after 5 s resend, max 3 times. 3-2-1 beeps + big countdown before each change. Workout pauses when the belt stops, resumes on restart. Incline Off mode never touches incline, workouts included.
**Snapshots.** Manual (flash, pre-selected) + optional auto: random, max 3/session, first 4–14 min in, silent, unticked. Never tied to climbs or hard reps ("no summit shots"). Keep max 6, cleared each session. Strava's public API can't attach photos → save to Photos. Later: AI photoreal snapshot = clean frame (+ depth) → image model via a relay (key never in the app) → redraw the exact HUD on top.
**Strava.** Client secret was reset (old one dead) and is stored as an encrypted Cloudflare Secret. New Strava API apps cap connected athletes — ask Strava to raise it before sharing. Uploads are indoor/virtual activities with a lap per workout block.
**Sharing with friends (maybe, later).** Strava login and settings are already per device. Real work would be a course format (folder: route + elevation, model chunks, mood, thumbnail), a course picker, and a separate "courses" repo friends can PR into. Code changes stay Jim-only.
**Art direction thinking.** Cohesion beats realism: Zwift looks good through hero landmarks every few hundred metres, dense road-level detail (grass, walls, verges), one consistent painted style and composed views. Options to style-frame (Jim may use Nano Banana): "Zwift-plus" painterly realism, cel-shaded/anime with ink lines, flat graphic layered fog (Firewatch). Jim leans realism. Tactics: one pack family across themes (Synty Polygon paid, Quaternius/Kenney free), CC0 textures (Poly Haven, ambientCG), let the engine enforce the look (palette, light, fog, grade, optional outline shader), pick scenery first and build characters to match it. Real terrain from OS elevation data is an option. Environment moods so far: Scottish Highlands back roads (default), dawn, coast, night.
**Characters.** Jim may make character sheets of himself in run/ride kit. Rule against to-do bloat: try the cheapest path first and judge it against a bar (character sheet → Magnific/Tripo image-to-3D → remesh to ~10–20k tris with baked normals → Mixamo), and only try alternatives if it fails. MetaHuman is allowed outside Unreal but is a sledgehammer (hair/materials don't carry over, no kit or bike, photoreal only). Never AI-generate the bike (thin tubes and spokes get mangled). Cycling legs: drive them from the cranks in code (feet locked to the pedals) rather than a canned loop.
**Splats.** Jim has an old Insta360 Go and GoPro (no 360 camera). Ready-made outdoor splats exist (Insta360 research scenes on Hugging Face, non-commercial). A 5 km route would be chunked, ~1–3 GB compressed (SPZ): fine on the Mac, a stretch on iPad, too heavy for Apple TV. Start with a 200 m test if pursued. Unreal is installed (crashing on launch — to look at); C4D trial ended (may buy at Black Friday). Genie-style generated worlds: fun later, no API.
**Apple TV practicalities.** Pair via Apple TV Settings → Remotes and Devices → Remote App and Devices, then Xcode → Devices and Simulators; Developer Mode toggle on first install. The free account's 7-day expiry could be handled by a scheduled rebuild/reinstall. Xcode 26.3+ exposes an MCP server (`xcrun mcpbridge`) if Xcode-driven builds ever help. Apple TVs limit simultaneous BLE sensors: test treadmill + HR together early if the TV ever drives the hardware. Jim mostly runs in front of a Samsung Frame via the Apple TV, so the TV is the target experience.
**Controls (later).** Ring remote probably sends media keys → `MPRemoteCommandCenter` next/prev = ±0.5 km/h for freestyle fartlek (needs Now Playing status); a proper BT game controller is the fallback. Siri Remote buttons; voice is uncertain. KICKR hood buttons and gears are proprietary Wahoo BLE (the web app has a Bluetooth explorer to probe them).
**Bike physics (web app).** Validated against standard calculators: 200 W → 34 km/h flat, ~18 km/h at 4 % (77 kg total). Starting from standstill feels slow (honest physics); maybe add a Zwift-style kick. KICKR's own speed is shown for comparison; it uses the Wahoo app's weight setting.
**Coached runs (idea, 12 Nov — on/off option "coached / uncoached").** Treadmill reps are at fixed pace, so the signal is the *body's response* per rep: HR at the end of each rep vs rep 1 (drift), how fast HR climbs into the rep, and HR drop over the recovery (e.g. bpm fallen after 60 s). Short, calm cues delivered at the start of a recovery (never mid-rep), e.g. "Rep 6 cost 7 bpm more than rep 2 at the same pace" or "Recovered 32 bpm in 60 s, best of the session". Can compare against Jim's own history of the same workout (Garmin/Strava data). Post-run: a short summary, possibly written by Claude via a relay. Personality option: a gruff old-school-trainer voice (Jim's reference: Mickey from Rocky) with the odd word of encouragement, plus long-run boredom breakers ("over the hump, 2 km and we'll call it a night"). Keep it rare and earned — tied to real moments (halfway, last rep, a strong recovery), with a tone setting (off / straight / gruff) so it can't go twee. Optionally spoken (AirPods) as well as on screen. Voice also for plain announcements — block start/end, rep counts, 3-2-1 (Kinni has this; handy when not watching the screen): start with built-in AVSpeechSynthesizer (offline, ducks music); a custom gravelly-trainer voice later via a designed TTS voice — an original voice, not a clone of a real actor. Event cues/alerts in general: subtle, brief, few (Jim finds Zwift's pop-ups annoying).

**Other hardware/ideas.** Concept2 BikeErg (PM5 BLE): display/record only, no resistance control. iPad mini: back-burner; gym treadmills a distant maybe. HUD design directions exist as a design artifact: A Glass, B Film (letterbox), C Instrument strip, B-for-intervals (pace + target, metres to go, rep strip). Jim will choose fonts himself.
